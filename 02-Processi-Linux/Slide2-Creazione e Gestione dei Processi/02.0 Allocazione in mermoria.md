## Il Segmento Statico: Codice e Costanti (Bassi Indirizzi)
Alla base dello spazio utente si trovano le fondamenta del programma, ovvero i dati immutabili caricati direttamente dal file eseguibile (formato ELF). Questa zona è divisa in tre sezioni principali: la sezione .text contiene le istruzioni macchina effettive eseguite dalla CPU ed è protetta in scrittura (r-x) per impedire modifiche al codice; la sezione .rodata ospita le stringhe letterali e le costanti globali, protetta da scrittura ed esecuzione (r--) per motivi di sicurezza. Subito sopra troviamo la sezione .data, che contiene le variabili globali inizializzate con un valore iniziale esplicito (es. int x = 5;), l'unica parte di questo blocco contrassegnata come modificabile (rw-).
## Il Blocco BSS: L'Ottimizzazione dei Dati Non Inizializzati
Subito dopo il segmento statico risiede la sezione .bss (Block Started by Symbol). Quest'area ha una particolarità: contiene tutte le variabili globali e statiche che il programmatore non ha inizializzato o che ha impostato esplicitamente a zero. Per ottimizzare lo spazio sul disco fisso, il file eseguibile non memorizza fisicamente questi zeri, ma ne indica solo la dimensione complessiva. Al momento dell'avvio del processo, il kernel Linux interviene allocando pagine di memoria anonima e azzerandole completamente in RAM, garantendo che queste variabili abbiano un valore di partenza sicuro e prevedibile (rw-).
## Lo Heap e lo Stack: Le Due Aree Dinamiche Contrapposte
Per evitare di sovrapporsi, le due principali aree di memoria dinamica sono posizionate ai lati opposti dello spazio utente e crescono l'una verso l'altra. Lo Heap (Mucchio) parte dal basso, subito dopo la sezione BSS, e cresce verso l'alto (indirizzi più alti); viene gestito manualmente dal programmatore tramite funzioni come malloc() o operatori come new ed è ideale per dati la cui dimensione è nota solo a runtime. Al contrario, lo Stack (Pila) si trova in cima allo spazio utente e cresce verso il basso (indirizzi più bassi); è gestito in modo totalmente automatico dall'hardware e dal compilatore con una logica Last-In, First-Out (LIFO), ospitando le variabili locali e i parametri delle funzioni durante la loro esecuzione.
## Il Segmento Mappature: Librerie e Grandi Allocazioni (Area Centrale)
Nello spazio intermedio che separa lo Heap e lo Stack si estende il Memory Mapping Segment. Questa vasta area centrale viene gestita principalmente attraverso la chiamata di sistema mmap() e svolge due ruoli cruciali. Da un lato, accoglie il codice e i dati delle librerie condivise (.so, come la libreria standard del C), permettendo a più processi di condividere le stesse pagine fisiche di codice in sola lettura per risparmiare RAM. Dall'altro, viene utilizzata per mappare file direttamente dal disco in memoria o per allocare blocchi di memoria anonima di grandi dimensioni (solitamente sopra i 128 KB), superando i limiti di frammentazione del tradizionale Heap.
## I Meccanismi di Sicurezza e Controllo: MMU e ASLR
L'intero spazio di indirizzamento virtuale è strettamente sorvegliato dall'hardware della MMU (Memory Management Unit) in combinazione con il kernel. Ogni violazione dei permessi impostati sulle singole aree (come il tentativo di scrivere nella sezione del codice o di eseguire istruzioni memorizzate nello Stack) viene intercettata immediatamente, causando l'interruzione del programma tramite un Segmentation Fault. Inoltre, per prevenire attacchi informatici mirati che sfruttano la prevedibilità della memoria, Linux applica la tecnologia ASLR (Address Space Layout Randomization), che altera casualmente gli indirizzi di partenza di Stack, Heap e Mappature a ogni singolo avvio del processo.

## esempio pratico in codice C 

Ecco un codice completo in C scritto appositamente per mostrare in tempo reale la disposizione delle varie aree di memoria all'interno dello spazio di indirizzamento virtuale.
Il programma dichiara variabili in sezioni diverse e ne stampa l'indirizzo virtuale in esadecimale.
## Il Codice Sorgente (mappa_memoria.c)

#include <stdio.h>#include <stdlib.h>#include <sys/mman.h>#include <unistd.h>
// 1. Variabile globale inizializzata -> Sezione .dataint globale_inizializzata = 42;
// 2. Variabile globale NON inizializzata -> Sezione .bssint globale_non_inizializzata;
// 3. Costante globale -> Sezione .rodataconst char* stringa_costante = "Sono in .rodata";
void funzione_esempio() {
    // Questa funzione serve solo per mostrare l'indirizzo del codice
}
int main() {
    // 4. Variabile locale -> [stack]
    int variabile_locale = 10;

    // 5. Allocazione dinamica piccola -> [heap] (tramite brk/sbrk internamente)
    int* ptr_heap = (int*)malloc(sizeof(int));

    // 6. Allocazione dinamica grande -> Memory Mapping Segment (tramite mmap)
    // 200 KB superano la soglia standard di malloc per l'uso di mmap
    void* ptr_mmap = malloc(200 * 1024);

    printf("=== MAPPA DELLO SPAZIO DI INDIRIZZAMENTO VIRTUALE ===\n\n");

    // Indirizzi Bassi (Codice e Costanti)
    printf("[BASSO] .text (Codice)      : %p\n", (void*)&funzione_esempio);
    printf("[BASSO] .rodata (Costanti)  : %p\n", (void*)stringa_costante);
    
    // Dati Modificabili Statici
    printf("[MEDIO] .data (Glob. Iniz.) : %p\n", (void*)&globale_inizializzata);
    printf("[MEDIO] .bss (Glob. Non In.): %p\n", (void*)&globale_non_inizializzata);
    
    // Aree Dinamiche
    printf("[CRESCE UPG] [heap]         : %p\n", (void*)ptr_heap);
    printf("[CENTRO] mmap / Librerie    : %p\n", ptr_mmap);
    printf("[ALTO]  [stack] (Locali)    : %p\n\n", (void*)&variabile_locale);

    printf("Il PID del processo e': %d\n", getpid());
    printf("Premi INVIO per terminare il programma...");
    
    // Mantiene il processo attivo per permetterti di controllare /proc/PID/maps
    getchar(); 

    // Pulizia
    free(ptr_heap);
    free(ptr_mmap);
    return 0;
}

## Come compilarlo ed eseguirlo
Puoi compilare ed eseguire il programma direttamente dal tuo terminale Linux:

gcc mappa_memoria.c -o mappa_memoria
./mappa_memoria

## Analisi dell'Output (Cosa notare)
Quando esegui il programma, noterai una chiara progressione degli indirizzi:

   1. La scala numerica: Gli indirizzi di .text e .rodata inizieranno con numeri esadecimali molto piccoli (es. 0x55... o 0x40...).
   2. La distanza dello Stack: L'indirizzo dello [stack] sarà enormemente più grande degli altri (es. inizierà con 0x7ff...), confermando che si trova in cima allo spazio virtuale.
   3. L'area intermedia: L'indirizzo restituito dalla grande allocazione ptr_mmap si posizionerà nella via di mezzo (es. 0x7f8...), al di sotto dello stack ma sopra l'heap.
   4. L'effetto dell'ASLR: Se premi INVIO, chiudi il programma e lo riavvii una seconda volta, noterai che gli indirizzi di [stack], [heap] e mmap saranno completamente cambiati. Le distanze relative rimarranno simili, ma la base sarà randomizzata.
